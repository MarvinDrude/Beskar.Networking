# Job Handlers, Source Generator & Progress Streaming

`Beskar.Jobs` provides strongly-typed handler interfaces, a Roslyn Incremental Source Generator (`BeskarJobGenerator`), and real-time progress and result streaming over MQTT v5.0.

---

## 1. Handler Interfaces

Job handlers implement one of two interfaces in `Beskar.Jobs.Common.Interfaces`:

### A. Void Handler (`IJobHandler<in TArgs>`)
Use `IJobHandler<TArgs>` when a job performs an action without returning a result payload:

```csharp
public interface IJobHandler<in TArgs>
{
   public ValueTask ExecuteAsync(IJobExecutionContext<TArgs> context, CancellationToken ct = default);
}
```

### B. Result-Producing Handler (`IJobHandlerWithResult<in TArgs, TResult>`)
Use `IJobHandlerWithResult<TArgs, TResult>` when a job produces a typed output that should be persisted on the job record and broadcast to watching clients upon completion:

```csharp
public interface IJobHandlerWithResult<in TArgs, TResult>
{
   public ValueTask<TResult> ExecuteAsync(IJobExecutionContext<TArgs> context, CancellationToken ct = default);
}
```

### C. Execution Context (`IJobExecutionContext<out TArgs>`)
Every running handler receives an `IJobExecutionContext<TArgs>` providing full execution metadata and progress reporting:

| Member | Type | Description |
| :--- | :--- | :--- |
| `JobId` | `string` | Unique identifier of the running job instance. |
| `JobType` | `string` | Logical job type identifier (e.g., `"orders.validate"`). |
| `Queue` | `string` | Queue name on which the job was dispatched (e.g., `"orders"`). |
| `Attempt` | `int` | Current 1-based execution attempt (`1..MaxAttempts`). |
| `MaxAttempts` | `int` | Maximum configured attempts before dead-lettering. |
| `WorkerId` | `string` | Identifier of the `JobWorker` executing this job. |
| `Arguments` | `TArgs` | Deserialized job arguments payload. |
| `Metadata` | `IReadOnlyDictionary<string, string>` | Custom key-value headers attached when the job was enqueued. |
| `ReportProgressAsync(...)` | `ValueTask` | Publishes a live progress update (`0..100%`) and optional status message. |

## 2. Source-Generated Job Descriptors (`[GeneratedJobHandler]`)

Decorating a `partial` handler class with `[GeneratedJobHandler(jobType, Queue = ...)]` triggers [`BeskarJobGenerator`](https://github.com/MarvinDrude/Beskar.Networking/blob/master/Jobs/Beskar.Jobs.Generator/BeskarJobGenerator.cs) at compile time.

### Declaring a Generated Handler

```csharp
using Beskar.Jobs.Common.Attributes;
using Beskar.Jobs.Common.Interfaces;

public sealed record TranscodeVideoArgs(string AssetId, string Codec);
public sealed record TranscodeVideoResult(string OutputUri, double DurationSeconds);

[GeneratedJobHandler("media.video.transcode", Queue = "media")]
public sealed partial class TranscodeVideoJobHandler : IJobHandlerWithResult<TranscodeVideoArgs, TranscodeVideoResult>
{
   public async ValueTask<TranscodeVideoResult> ExecuteAsync(
      IJobExecutionContext<TranscodeVideoArgs> context,
      CancellationToken ct = default)
   {
      await context.ReportProgressAsync(50, $"Encoding {context.Arguments.AssetId} ({context.Arguments.Codec})...", ct);
      await Task.Delay(200, ct);
      return new TranscodeVideoResult($"s3://encoded/{context.Arguments.AssetId}.mp4", 0.2);
   }
}
```

### What the Generator Emits
`BeskarJobGenerator` implements `IGeneratedJobDescriptor` on your partial class (supporting top-level and arbitrarily nested `partial` classes, structs, and records):

```csharp
// <auto-generated/>
#nullable enable

partial class TranscodeVideoJobHandler : global::Beskar.Jobs.Common.Interfaces.IGeneratedJobDescriptor
{
   public const string JobType = "media.video.transcode";
   public const string DefaultQueue = "media";
   public static string GeneratedJobType => JobType;
   public static string GeneratedQueue => DefaultQueue;
}
```

### Compile-Time Analyzer Diagnostics
`BeskarJobGenerator` validates handler declarations at build time and emits diagnostics if misconfigured:

| Diagnostic ID | Severity | Condition |
| :--- | :---: | :--- |
| **`JOBGEN001`** | Error | The handler type (or one of its enclosing types) is not declared `partial`. |
| **`JOBGEN002`** | Error | The `jobType` argument passed to `[GeneratedJobHandler]` is empty or whitespace. |
| **`JOBGEN003`** | Error | The `Queue` named argument passed to `[GeneratedJobHandler]` is empty or whitespace. |
| **`JOBGEN004`** | Error | The decorated type does not implement `IJobHandler<TArgs>` or `IJobHandlerWithResult<TArgs, TResult>`. |

## 3. Registering Handlers on `JobWorkerBuilder`

`JobWorkerBuilder` supports three registration styles:

### Style 1: Source-Generated Registration (Recommended)
Automatically registers the handler's `GeneratedJobType` and subscribes the worker to `GeneratedQueue`:

```csharp
var worker = JobWorkerBuilder.Create()
   .WithWorkerId("worker-media-01")
   // Registers "media.video.transcode" AND subscribes to queue "media"
   .RegisterGeneratedHandlerWithResult<TranscodeVideoJobHandler, TranscodeVideoArgs, TranscodeVideoResult>()
   // For void IJobHandler<TArgs> handlers:
   .RegisterGeneratedHandler<CleanupTempFilesJobHandler, CleanupArgs>()
   .UseTcp(endPoint)
   .Build();
```

### Style 2: Explicit Class / Instance Registration
```csharp
var worker = JobWorkerBuilder.Create()
   .SubscribeQueue("media")
   .RegisterHandlerWithResult<TranscodeVideoArgs, TranscodeVideoResult>("media.video.transcode", new TranscodeVideoJobHandler())
   .UseTcp(endPoint)
   .Build();
```

### Style 3: Inline Lambda / Delegate Registration
```csharp
var worker = JobWorkerBuilder.Create()
   .SubscribeQueue("default")
   .RegisterHandler<string>("system.ping", async (ctx, ct) =>
   {
      await ctx.ReportProgressAsync(100, $"Pong from {ctx.WorkerId}", ct);
   })
   .RegisterHandlerWithResult<int, int>("math.square", (ctx, _) =>
      ValueTask.FromResult(ctx.Arguments * ctx.Arguments))
   .UseTcp(endPoint)
   .Build();
```

## 4. Enqueuing & Streaming Progress (`JobClient`)

### A. Real-Time Progress Stream (`WatchJobStatusAsync`)
Status updates on `jobs/status/{jobId}` are published with the **MQTT Retain flag** set. This means even if a client calls `WatchJobStatusAsync` *after* the job has already started or finished, the broker immediately delivers the latest snapshot without race conditions.

```csharp
var enqueueResult = await client.EnqueueGeneratedWithResultAsync<TranscodeVideoJobHandler, TranscodeVideoArgs, TranscodeVideoResult>(
   new TranscodeVideoArgs("clip-42", "av1"));

var jobId = enqueueResult.Success!.JobId;

// Automatically terminates when update.IsTerminal becomes true (Succeeded, Failed, Cancelled, DeadLettered)
await foreach (var update in client.WatchJobStatusAsync(jobId))
{
   Console.WriteLine($"[{update.Status,-13}] Attempt #{update.Attempt} | {update.ProgressPercent,3}% | {update.Message}");
}
```

### B. One-Shot Result Awaiting (`WaitForJobResultAsync`)
If you only need the final typed result and do not need intermediate progress bars, call `WaitForJobResultAsync<TResult>`:

```csharp
var result = await client.WaitForJobResultAsync<TranscodeVideoResult>(
   jobId,
   timeout: TimeSpan.FromSeconds(30));

if (!result.Failed)
{
   Console.WriteLine($"Encoded URI: {result.Success!.OutputUri}");
}
```

## 5. Custom Payload Serialization (`IJobPayloadSerializer`)

By default, `Beskar.Jobs` uses [`JsonJobPayloadSerializer`](https://github.com/MarvinDrude/Beskar.Networking/blob/master/Jobs/Beskar.Jobs.Common/Serialization/JsonJobPayloadSerializer.cs) (which also passes raw `byte[]` arguments through with zero JSON base64 overhead).

To use MessagePack, Protobuf, or MemoryPack, implement `IJobPayloadSerializer` and pass `.WithSerializer(...)` to `JobClientBuilder`, `JobWorkerBuilder`, and `JobSchedulerBuilder`:

```csharp
public interface IJobPayloadSerializer
{
   public byte[] Serialize<T>(T value);
   public T? Deserialize<T>(ReadOnlySpan<byte> payload);
}
```
